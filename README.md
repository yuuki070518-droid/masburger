# MAS BURGER

一人称のハンバーガー屋シミュレーター。ブラウザで動き、同じルームの人と同じ店で一緒に働ける。

## 置くファイル（GitHub Pages などにはフォルダごと）
- `index.html` … ゲーム本体
- `net.js` … 通信（P2P＋中継）
- `security.js` … 通信データの検証
- `lib/` … three.js r128 本体と GLTFLoader / SkeletonUtils / BufferGeometryUtils、mqtt.js（いずれも MIT）
- `assets/chars/` … 人物モデル（Kenney「Mini Characters」CC0）
- `assets/city/` … 窓の外の建物（Kenney「City Kit (Commercial)」CC0）
- `assets/tex/` … 床・壁・天井などの質感（ambientCG CC0、`assets/tex/CREDITS.txt`）
- `sfx/` … 効果音
- `bunbun-burger/` は旧版（触っていない）

ローカルなら `index.html` をダブルクリックで開いてよい。`file://` で開いたときだけ、画像・モデル・効果音を埋め込んだ `assets/bundle.js` を読む（ブラウザが別ファイルの画像やモデルを直接読ませないため）。
素材（`assets/`・`sfx/`）を差し替えたら作り直す：

```bash
cd ~/Downloads/masburger-main && python3 tools/make_bundle.py
```

## 操作（初期設定。Esc / Tab 以外は設定画面の「キー設定」で変えられる）
| 操作 | キー |
|---|---|
| 移動 | W A S D（矢印キーでも可） |
| ダッシュ（押している間） | 左Shift（歩き 3.2m/秒 → 7.4m/秒） |
| しゃがむ（押している間） | C |
| ジャンプ | Space |
| 使う・置く / 具材を戻す / 包む | E（左クリック）/ Q（右クリック）/ T |
| 設定を開く・閉じる | Esc |
| 通信状況を表示（マルチのみ・押している間） | Tab |
| 全画面の切り替え | F |

**開店と閉店：** 一日は「準備中」から始まる（お客さんは来ない・時計は止まる）。入口の扉の札を E で OPEN にすると開店。もう一度 E を2回押すと CLOSED（閉店）になり、新しいお客さんが来なくなる。残っている人に出し終えると一日が終わる。営業時間（21時）になると自動で閉店。
**ジャンプ：** テーブル・椅子・厨房の真ん中の作業台・受け渡しカウンターに飛び乗れる・飛び越えられる（壁ぞいの調理台は不可）。頭は天井で止まる。
**メニューの解禁：** 1日目はハンバーガー・チーズバーガー・ポテト・コーラ（ケチャップ）だけ。発注端末の「メニュー」で 野菜トッピング／ソース追加／ドリンク追加／サイド追加／ダブル・タワー／ベーコン／シェイク／フィッシュバーガー を買うと、お客さんがそれを注文するようになり、必要な具材も仕入れられるようになる。

Esc で設定を開くとカーソルを自由に動かせます。ソロ（ルームに自分だけの場合も含む）では、時計・調理・お客さんの待ち時間が止まります。マルチでは自分の操作だけが止まり、店の時間は進みます。設定を閉じると再開します。発注端末は Esc で閉じます。

ブラウザが Esc を先に受け取った場合も、マウスのロック解除を検知して設定を開きます。ブラウザによっては再開時に画面のクリックが必要です。
Chrome などでは F で全画面にすると、Esc を短く押しても全画面が解除されない（長押しで解除）。Safari は Esc で解除される。

## マルチプレイのしくみ（2026-11-12 改修）
- プレイヤー同士は **WebRTC で直接つながる（P2P）**。相手探しと接続の手続きだけ公開 MQTT ブローカーを使う。
- 直接つながれない相手（会社や携帯回線の一部）とは、自動で公開ブローカー経由の **中継** になる。中継は遅延 0.3〜0.7 秒程度。
- 左下のプレイヤー一覧に経路と往復遅延を表示。Tab を押している間は、自分と各参加者間の往復遅延（RTT）を ms で一覧表示する。直結・中継の両方を測定し、未測定や古い値は「測定中」と表示する。
- 中継の測定情報は通常の配信に同梱する。表示値には相手側の送信待ちも含まれ、画面の補間による遅れとは異なる。
- 店長（ホスト）のタブが裏に回っても、店の進行と配信は止まらない。
- `?netdebug=1` を付けて開くと、接続の様子がコンソールに出る。

### 改修前後の実測（ホスト＋子2人が自動で操作し続ける30秒、公開ブローカー経由）
| | 改修前 | 改修後（直結） | 改修後（1人だけ中継） |
|---|---|---|---|
| 子の操作がホストで確定するまで | 中央値 10 秒 | 数 ms＋回線の往復 | 中央値 0.66 秒 |
| ホスト→子の状態の遅れ | 中央値 7.8 秒（最大 45 秒） | 数 ms＋回線の片道 | 中央値 0.35 秒 |
| 子の操作がホストに届いた割合 | 約 3 割 | 全部 | 全部 |
| 子の画面の置き物の数（ホストと一致するか） | ずれる | 一致 | 一致 |

原因と方針の詳細は `docs/codex/`（Codex と相談した記録と決定事項）。

## 段ボール配送（新要素）
発注端末で頼んだ食材は、厨房左手前の「搬入口」に段ボールで届く。運んで冷蔵庫・冷凍袋の棚・カップ置き場で E を押すと開けて補充される（そこで初めて在庫に入る）。床の箱は通れない。営業時間外の発注は次の開店時に届き、開けなかった箱は翌日に持ち越す。

## 片付け（新要素）
イートインのお客さんが帰ると席に「食べ終わったトレー」が残り、帰る人は時々床にゴミを落とす。E で拾ってゴミ箱へ（入口脇にもある。ゴミは手に5個まで重ねられる）。汚れるほど新しいお客さんの我慢とチップが減り、HUD に今の影響が出る。閉店時に残った汚れは清掃代。設備「トレー返却口」で半分のお客さんが自分で返してくれる。ノーマル/イージーでも一部のお客さんは店内で食べていく。

## 特別なお客さん

新しい客の20%が、Claude のマスコットをイメージしたオレンジ色の四角い生物になる。人型の客に近い高さ（1.8m）で、歩行・着席・リアクションに対応。注文や待ち時間は普通の客と同じ。客ごとのシードで見た目を決めるので、マルチでも全員に同じ姿が見える。モデルは three.js の箱から作り、追加の画像・GLBファイルは不要。

## 受信データと配信設定

操作・状態の形式と件数を検証し、ルームコードは暗号論的乱数で生成する。公開ブローカーには参加者・店長の認証機能を実装していない。店長固定は単純な後出しクレームへの対策で、サーバー認証の代わりにはならない。診断項目ごとの対応状況とHTTPヘッダーの設定例は [docs/security-review.md](docs/security-review.md) を参照。
