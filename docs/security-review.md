# 2026-11-16 セキュリティ診断への対応

対象ソース: main `67f6e7980c0821e5db26e6084cc867fc9a87e7dc`。診断の10件は重複を含む。
公開サイトのHTTPヘッダーも2026-11-16に再確認し、CSP・X-Frame-Options・nosniff は未設定だった。
このPRはソース変更であり、公開サイトへの反映やサーバー設定の完了を意味しない。

| 指摘番号 | 対応 | 残る点 |
| --- | --- | --- |
| 1・5 店長権限 | 進行中・参加者間で確定した店長を固定し、後から小さい `h` を送っても交代させない。店長退出時は交代を許す | 初回の店長決定、通信の分断、公開ブローカーでの送信者偽装は認証できない。サーバーによる権限発行と検証が必要 |
| 2 CSP | HTMLのmeta CSPを追加。スクリプトは同一オリジンと内容ハッシュで許可。Worker・画像・音・フォント・通信先を列挙 | HTTPヘッダーを検査する診断では依然「ヘッダーなし」。独自ブローカーを使う場合は `connect-src` を見直す |
| 3 埋め込み制限 | `deploy/nginx-security.conf` に `frame-ancestors 'self'` と `X-Frame-Options` の設定例を用意 | サーバー/CDN側で適用が必要。meta CSPでは `frame-ancestors` は効かない |
| 4 MIME推測抑止 | 同じ設定例に `X-Content-Type-Options: nosniff` を用意 | サーバー/CDN側で適用が必要 |
| 6・7 操作配列 | 許可した操作だけを受け付け、整数・配列範囲・座標・フェーズ・連番を検証。座標を対象面にクランプ。24件/配列、各参加者20件/秒・瞬間40件。失敗した操作だけを破棄 | 開店依頼・購入は従来どおり協力プレイの正規操作。クライアント自身の改造を防ぐものではない |
| 8 プロトタイプ参照 | 外部キーの辞書を `Object.create(null)` に変更。危険なキーと数値以外の客IDを受信時に拒否 | 基盤の認証とは別の入力検証 |
| 9 配信データ量 | 受信文字列128KiB、再帰深さ・ノード数・各配列長を検査。客32人、置き物90個、通知8件、口コミ6件に制限。相手の管理も32件に制限 | 公開ブローカー全体への流量や接続試行の制限は、その運営側・認証付き専用サーバーで必要 |
| 10 ルームコード | `crypto.getRandomValues` の16バイトを32文字の16進数にする。参加用の入力上限も32文字に変更。従来の短いコードには引き続き参加可能 | 旧ルームの強度は変わらない。コードは認証ではなく、公開MQTTでワイルドカード購読を制限する仕組みもない |

追加で、受信した口コミ本文をHTMLとして解釈しないようエスケープし、集計画面に渡す数値と文字列の形式も検査した。

## この構成で保証できないこと

GitHub Pages版の `net.js` は、公開MQTTとWebRTCで通信する。`window.claude.use('room')` はこのファイルが提供する互換APIで、公開版の参加条件にClaudeへのログインは含まれない。
診断文中の「招待＋Claudeログイン必須」という前提は、この公開版には当てはまらない。

店長権限を安全に認証するには、認証付きの専用サーバー/ブローカーでルームの参加権限と店長を管理し、送信者と状態の署名・権限を検証する必要がある。
今回の店長固定は、同じルーム内での単純な後出しクレームを抑えるための改善であり、乗っ取り対策の完了とは扱わない。

GitHub Pages上でnginx用設定ファイルを置いてもHTTPヘッダーは変わらない。3・4を完了するには配信環境の変更またはヘッダーを設定できるCDNが必要。
公開環境の変更・移転はこのPRでは行わない。

## 検証

```sh
node tools/security.test.cjs
python3 tools/update_csp.py
```

`index.html` のインラインJavaScriptを変更した場合は `update_csp.py` でハッシュを更新する。
コードの差分だけを変更しハッシュを更新しないと、CSPがそのスクリプトをブロックする。

ブラウザでは通常の起動、ソロの停止と再開、マルチの進行、Tab表示を確認する。
不正操作の破棄と確定後の `h:1` クレームの無効化は、ローカルのテスト用ルームで検証する。
実際の公開ブローカーに対する侵入・総当たり・負荷試験は行わない。
